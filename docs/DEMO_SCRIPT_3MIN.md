# 3 分钟现场演示脚本

> 目标：让面试官不看 API 文档也能理解「可迁移、受控销售数据分析」闭环。
> 前置条件：FastAPI 已启动，PostgreSQL 就绪，本地或远程 Qwen 可用，`.env` 配置管理员/分析员账号。

## 第 0 步（开场，约 15 秒）

进入「知枢 Nexus」工作台，切换管理员账号，点开「数据集管理」页。一句话点题：

> 这个系统不是只对一张固定销售表写死的。任何符合接入契约的销售 CSV 或 Parquet，经过画像、字段映射、指标确认后，都能复用同一套 Agent 分析流程。

## 第 1 步（上传并画像，约 50 秒）

1. 上传准备好的第二套销售数据 `cross_dataset_sales.csv`（列名 `order_no / gross_amount / qty / source / region_code / sale_date`，与 demo 表完全不同）。
2. 点「开始分析」：系统创建隔离 staging schema，输出字段画像、候选角色和质量报告。
3. 点开质量报告，指出「全部通过，无严重问题」。

> 关键点：字段角色（金额、数量、渠道、时间…）不是写死列名，而是来自 `propose_mapping` 的确定性语义映射。

## 第 2 步（确认映射与指标，约 40 秒）

1. 展示字段映射草稿（`gross_amount → 金额`、`qty → 数量`、`source → 渠道`…），点「确认字段映射」。
2. 点「生成指标建议」，展示自动建议的销售额/订单数/销量/客单价，点「确认」。
3. 点「标记为可用」，数据集进入 `ready`。

> 关键点：模型只能建议，口径必须管理员确认；`ready` 数据集至少有一个可查询指标。

## 第 3 步（分析员查询，约 50 秒）

1. 切换到分析员账号，回到分析工作台。
2. 顶部「数据范围」选择刚就绪的数据集（显示名称、版本、可用指标）。
3. 提问：`按渠道统计最近一个季度的销售额，并给出环比变化。`
4. 展示：结构化分析计划 → SQL 生成 → 只读安全与业务口径校验 → 执行 → 图表与结论。
5. 点开执行记录/证据，指出数据集版本、指标口径和 SQL 都可以追溯。

> 关键点：Agent 只基于当前选中数据集的 Schema 和已确认指标生成 SQL，无法跨数据集 JOIN。

## 第 4 步（对比固定 demo 数据，约 20 秒）

在「数据范围」切回「自动」，用同一问题分析固定 demo 数据，展示同样的计划语义生成了不同字段的 SQL。

> 收尾：迁移能力来自接入契约和语义映射，不修改 Agent 主工作流代码。

## 时间把控

| 步骤 | 时长 | 必须讲到 |
|---|---|---|
| 开场 | 15s | 不是固定表写死 |
| 上传+画像 | 50s | 隔离 schema、质量报告、语义映射 |
| 映射+指标+ready | 40s | 管理员确认口径、指标版本化 |
| 分析员查询 | 50s | 数据集范围约束、计划/SQL/校验/图表、可追溯 |
| 对比 + 收尾 | 20s | 换数据不改主工作流 |
