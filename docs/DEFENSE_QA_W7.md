# W7-4 答辩题库

## 页面与部署

**问：为什么同时保留 `/health` 和 `/ready`？**  
**答：**`/health` 只证明进程还活着，`/ready` 还要确认 PostgreSQL 可连接且分析所需业务关系存在。把两者混为一谈会让平台在数据库未迁移完成时提前放入流量。

**问：为什么不能直接把本地 Ollama 暴露到公网？**  
**答：**本地地址只在开发机有效，暴露公网还会带来模型服务、密钥、数据出境和并发成本风险。公开部署必须使用受控内网模型服务或经过审查的远程适配器。

**问：页面为什么不能直接连接数据库？**  
**答：**浏览器会暴露数据库地址和凭据，并绕过权限、SQL 安全校验、审计和人工审批；所有查询必须经过服务器工作流。

**问：为什么公开演示要关闭请求状态、审批和原始 Trace？**
**答：**公开页面的访客共享一个演示身份，不能再把“同一 user_id”当作真正的所有权证明。关闭这些内部接口可以避免访客根据请求编号读取他人的状态、原始 SQL 和错误细节；页面只保留经过整理的中文进度与可信结果。

**问：当前限流为什么不能称为生产级限流？**
**答：**它只在单个 API 进程内按来源地址计数，能保护单实例演示的模型额度。多实例之间不共享计数，代理地址也需要可信配置；生产环境应在网关或 Redis 等共享设施中统一限流。

## 安全与审计

**问：请求体里把角色改成管理员可以吗？**  
**答：**不可以。角色来自服务器认证配置，请求中的 `user_id` 只能和服务器身份比对，不能由用户自行声明。

**问：为什么已经只读还要业务一致性校验？**  
**答：**只读只说明没有写入数据库，不说明指标公式、表关联、时间口径和权限范围正确；业务校验负责阻止“语法安全但业务错误”的查询。

**问：三类记录分别记录什么？**  
**答：**Checkpointer 保存工作流状态快照用于恢复；审计记录谁在什么时候请求、审批或查看了什么；执行 Trace 记录系统组件、耗时、重试和错误，便于定位故障。

## 评测与边界

**问：为什么不能宣称准确率 100%？**  
**答：**当前数字来自固定开发题和回归契约，证明代码在已知场景稳定，不代表冻结题、未知问题和生产数据上的泛化能力。还需要独立 holdout 和真实业务评审。

**问：为什么故障注入不放在公开页面？**  
**答：**故障开关只服务测试，不属于普通运营人员能力；公开暴露会制造不稳定体验，也可能触发重复执行和资源消耗。
