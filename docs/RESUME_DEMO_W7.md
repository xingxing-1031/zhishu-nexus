# W7-4 简历与演示材料

## 一页简历项目描述

### 零售运营可审计分析 Agent

面向运营人员的自然语言零售数据分析系统。用户问题经结构化分析计划和版本化指标字典约束后，经过混合检索、证据绑定、SQL 生成、SQLGlot 只读校验、业务一致性校验、权限控制和高风险人工审批，再由 PostgreSQL 执行并通过 SSE 返回表格、图表和执行记录。

- 使用 LangGraph 组织计划、检索、查询、安全、审批、执行和总结节点；用 PostgreSQL Checkpointer、审计日志和执行记录支持节点级恢复与问题定位。
- 使用 Pydantic、指标/Schema 白名单和请求幂等键限制模型输出；拒绝写操作、通配符、越权身份和不支持业务字段。
- 使用固定数据库快照和独立评测器完成 40 条开发题、20 条冻结题的评测基础；当前全量自动化回归 `399 passed`，桌面演示场景 `14/14` 通过，故障专项 `39 passed`。
- 页面提供中文用户提示、工作流进度、可信表格/图表、有限一轮澄清和人工审批状态；模型总结失败时保留可信查询结果并降级说明。
- 通过统一结构化模型适配器兼容本地 Ollama 与 OpenAI 兼容的远程 Qwen；已完成真实远程端到端分析验收，模型密钥只保存在服务器环境变量中。

> 不能写成“Agent 准确率 100%”或“生产级系统”。上面的数字是当前开发、页面和专项回归证据。

## 三分钟演示脚本

1. 打开演示页，先说明角色为服务器配置的分析员，页面不持有数据库连接。
2. 输入“最近30天各渠道销售额是多少？”，展示计划、检索证据、查询校验、执行、表格和柱状图。
3. 输入“哪个渠道最好？”，展示系统先追问，不生成 SQL、不访问数据库；补充“销售额，最近30天”后重新走完整链路。
4. 输入“你是谁？”和“好吧”，展示中文助手答复，说明对话类输入不会进入数据分析。
5. 输入“删除订单数据”或“查看订单所有字段”，展示在数据库连接前拒绝，并说明内部记录保留拒绝原因。
6. 以分析员输入“查询退款原因”，展示权限拒绝；再说明管理员审批接口不在公开演示中开放。
7. 最后打开执行记录，说明 Checkpointer、审计和系统 Trace 的职责不同；补充 `/health` 与 `/ready` 的部署边界。

## 演示禁忌

- 不现场展示数据库密码、模型密钥、完整 SQL 或未脱敏 Trace。
- 不把故障注入按钮放到普通用户页面。
- 不用开发集通过率推断真实业务泛化准确率。
- 不在没有批准的情况下执行审批请求。
