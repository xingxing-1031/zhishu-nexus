# W7-4 简历与演示材料

## 一页简历项目描述

### 零售运营可审计分析 Agent

面向运营人员的自然语言零售数据分析系统。用户问题经结构化分析计划和版本化指标字典约束后，经过指标/Schema 证据检索、证据绑定、SQL 生成、SQLGlot 只读校验、业务一致性校验、权限控制和高风险人工审批，再由 PostgreSQL 执行并通过 SSE 返回表格、图表和执行记录。

- 使用 LangGraph 组织计划、检索、查询、安全、审批、执行和总结节点；用 PostgreSQL Checkpointer、审计日志和执行记录支持节点级恢复与问题定位。
- 使用 Pydantic、指标/Schema 白名单和请求幂等键限制模型输出；拒绝写操作、通配符、越权身份和不支持业务字段。
- 使用固定数据库快照、人工 Gold 和独立分阶段评分器，对三种检索方案完成 `40 × 3 = 120` 次 development 工作流，并一次性验收 20 条 frozen holdout；用冻结结果识别 Planner、越界识别和结果匹配的泛化短板，避免把开发集通过率包装成准确率。
- 建立 `438` 项自动化回归，并在 CI 中覆盖 Python 3.11/3.12、Ruff、前端构建、Docker 镜像和空卷 PostgreSQL 初始化；公网固定场景验证正常分析、权限拒绝和管理员审批闭环。
- 页面提供中文用户提示、工作流进度、可信表格/图表、有限一轮澄清和人工审批状态；模型总结失败时保留可信查询结果并降级说明。
- 通过统一结构化模型适配器兼容本地 Ollama 与 OpenAI 兼容的远程 Qwen；已完成真实远程端到端分析验收，模型密钥只保存在服务器环境变量中。
- 公网部署提供固定分析员/管理员演示账号，身份由签名 Cookie 和服务端配置决定；后端按来源地址限流并限制返回行数，只有管理员可进入敏感字段审批和审计链路。

> 不能写成“Agent 准确率 100%”或“生产级系统”。development 六个核心阶段虽然为 `100%`，但已消费的 frozen holdout 核心通过率为 `35.00%`；简历正文强调评测方法和问题定位，不将任一结果外推为真实业务准确率。

## 面试可讲的量化证据

| 证据 | 当前结果 | 面试口径 |
|---|---:|---|
| Python 自动化回归 | `438 passed` | 覆盖模型、SQL 安全、权限、审批、幂等、重试、Trace、API 和部署资产 |
| Development 对照实验 | `40 × 3 = 120` 次 | 三种检索方案六个核心阶段均为 `100%`，但数据已用于调优，不代表泛化准确率 |
| Frozen holdout | `20` 条、核心通过率 `35.00%` | 一次性独立验收发现 Planner、越界识别和结果匹配短板；题集已消费，不再复用为独立验收 |
| 公网合成数据 | `130` 订单、`16` 商品、`4` 渠道、`30` 退款、`73` 天 | 用于稳定演示业务覆盖，不代表真实企业数据规模 |
| 公网固定场景 | 正常分析、权限拒绝、审批闭环均通过 | 正常分析返回 4 个渠道和柱状图；敏感查询在执行前被拒绝或暂停审批 |

## 三分钟演示脚本

1. 打开 `http://106.52.176.63/`，使用固定分析员演示账号登录，说明角色由服务器会话决定，页面不持有数据库连接。
2. 输入“最近30天各渠道销售额是多少？”，展示计划、检索证据、查询校验、执行、表格和柱状图。
3. 输入“哪个渠道最好？”，展示系统先追问，不生成 SQL、不访问数据库；补充“销售额，最近30天”后重新走完整链路。
4. 输入“你是谁？”和“好吧”，展示中文助手答复，说明对话类输入不会进入数据分析。
5. 输入“删除订单数据”或“查看订单所有字段”，展示在数据库连接前拒绝，并说明内部记录保留拒绝原因。
6. 以分析员输入“查询退款原因”，展示权限拒绝；切换固定管理员演示账号后，展示敏感字段查询的 SQL 预览、指纹、批准/拒绝和审计闭环。
7. 最后打开执行记录，说明 Checkpointer、审计和系统 Trace 的职责不同；补充 `/health`、`/ready`、HTTP 和单 VPS 的部署边界。

## 演示禁忌

- 不现场展示数据库密码、模型密钥、完整 SQL 或未脱敏 Trace。
- 不把故障注入按钮放到普通用户页面。
- 不用开发集通过率推断真实业务泛化准确率。
- 不在没有批准的情况下执行审批请求。
