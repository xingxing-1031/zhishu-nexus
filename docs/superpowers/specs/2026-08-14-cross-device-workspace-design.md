# 企析工作台跨设备会话与质感改版设计

## 目标

让企析在桌面和手机上都具备稳定的聊天体验：聊天内容可独立滚动，输入框始终固定在底部；两个固定演示身份分别在多个设备间自动同步会话；历史会话能够恢复完整回答；查询设置表达真实的结果偏好；视觉从暗青色工具界面升级为冰白、亮青绿、蓝色数据层次的企业工作台。

## 范围与约束

- 继续使用现有 React + TypeScript 前端、FastAPI 后端和 PostgreSQL 上下文存储。
- 不引入账号注册、空间码、扫码配对或设备管理，不改变现有两个固定演示账号的权限模型。
- 会话直接按已经认证的 `user_id` 保存；`analyst-demo` 和 `admin-demo` 之间完全隔离。
- 同一演示账号的所有登录端共享同一份历史。这意味着知道相同演示账号密码的人也能看到该身份的历史，此取舍在非公开生产使用的展示项目中接受。
- 现有未跟踪的 `docs/PROJECT_HANDOFF.md` 不参与本次变更。

## 方案

### 固定身份自动同步

前端登录后使用现有 HttpOnly 会话 Cookie 调用服务端会话接口，后端只从认证上下文取得 `user_id`，不接受前端指定其他用户。手机和电脑登录同一个演示身份后自动读取同一份服务端历史；切换身份后只读取该身份自己的历史。

服务端提供以下接口：

- `GET /agent/conversations`：返回当前认证身份最近会话及完整 turns。
- `PUT /agent/conversations/{conversation_id}`：为当前认证身份幂等保存一个会话。
- `DELETE /agent/conversations/{conversation_id}`：删除当前认证身份的指定会话。

登录成功后前端先拉取服务端数据，再合并当前浏览器中同一 `user_id` 的未同步数据，按 `updatedAt` 去重并限制为 8 个会话、每个会话 8 轮。写入失败不阻断聊天，界面显示“仅保存在本机”并保留本地副本，后续状态变化时自动重试。

### 历史回答兼容

服务端 turn 记录补充可恢复的响应 JSON、图表规格、表格行、阶段状态和 follow-up 上下文。读取时对旧记录执行兼容转换：缺少 `response` 时由 `summary` 构造最小 `AgentResponse`，缺少 outcome 时保留回答文本和失败状态。前端 `assistantFromTurn` 同时从 `response.answer`、`outcome.answer` 和 `summary` 取答案，保证历史记录不会出现空白回答。

### 稳定布局

工作台采用三段垂直结构：顶栏固定高度、聊天区 `minmax(0, 1fr)` 且唯一承担纵向滚动、输入区自适应但不参与聊天滚动。所有 grid/flex 中间节点补齐 `min-height: 0`，移动端使用 `100dvh` 与安全区 padding；输入框通过网格底行和层次阴影保持视觉固定，不采用会遮盖内容的全局 fixed。

### 查询设置

设置面板包含：

1. 最大返回行数：沿用当前会话权限上限。
2. 结果展示：自动、图表和表格、仅表格。该偏好随请求发送，后端在已有 `chart_spec` 基础上决定前端默认展开方式。
3. 自动打开证据详情：完成后是否选中本次请求并打开右侧证据抽屉。

### 视觉系统

- 画布 `#F6FAFB`，表面 `#FFFFFF`，浅青蓝环境色仅用于工作区背景带。
- 主操作色 `#0CA89B`，深色按压态 `#087F78`；数据图表使用 `#2563EB`，正文使用 `#172033`。
- 边框使用冷灰蓝 `#E2EAF0`，卡片半径保持 8px 以内；主按钮使用实心色、微高光和可见阴影，次按钮使用白底和明确 hover/pressed 状态。
- 通过 CSS 变量统一颜色、阴影和层级，保证桌面、手机和证据抽屉一致。

## 数据流

```text
登录固定身份 -> 服务端从 Cookie 解析 user_id -> 拉取该身份会话 -> 本地/远端按 updatedAt 合并
                                                    |
发送问题 -> Agent 请求（max_rows、display_mode、auto_open_evidence）
                                                    |
SSE 事件 -> live turn -> 完成后保存完整 turn -> 写入当前认证身份
```

## 失败处理

- 登录失效：停止远端同步并回到登录页，本地副本不删除。
- 同步接口超时/服务不可用：保留本地状态，显示“仅保存在本机”，恢复在线后自动重试。
- 两端同时更新同一会话：按会话 `updatedAt` 采用较新版本；同一时间戳按远端版本优先，避免重复轮次。
- 历史 turn 数据损坏：跳过损坏 turn，不影响同一会话其余内容，并显示可恢复提示。
- 移动端键盘打开：输入区使用安全区和滚动锚点，聊天区仍可手动上下滚动。

## 验收标准

- 桌面 1280x720、手机 390x844 下，连续 8 轮长回答可以在聊天区上下滚动，输入区位置不随滚动改变。
- 两个浏览器登录同一演示身份后能看到相同会话标题、问题、回答、图表、表格和执行信息；分析员与管理员身份互不可见。
- 重新加载并切换历史会话后，旧回答、表格和图表仍可见；旧版缺少 `response` 的记录至少显示 `summary`。
- 查询设置可保存并随下一次请求生效，最大行数仍受服务端权限上限约束。
- 视觉变量、按钮状态、抽屉和安全区在桌面与移动端无重叠、无横向溢出。
- 现有 Pytest、Ruff、前端 TypeScript 构建和新增同步/兼容测试全部通过。
