# 知枢 Nexus 品牌升级设计

## 目标

将当前产品品牌从“企析”统一升级为“知枢 Nexus”，使名称与现有企业 Agent 平台能力一致。知枢连接企业知识、经营数据和受控工具；零售运营分析继续作为专业数据能力保留，不再代表整个平台。

本次升级覆盖产品界面、应用元数据、代码仓库、运行标识和当前有效文档。改名不能改变 Agent 路由、权限、安全校验、会话同步或线上访问地址。

| 中文品牌 | 知枢 |
| 完整产品名 | 知枢 Nexus |
| 英文/代码 slug | `zhishu-nexus` |

Python 包 `retail_analytics_agent`、数据库名、既有 API 路由和数据模型暂不重命名。这些属于已经稳定的内部实现标识，批量迁移会扩大风险，却不会提升用户可见的品牌一致性。零售业务语义仍用于 Data Agent、指标字典和演示数据。

## 品牌定位与文案

知枢 Nexus 是“连接企业知识、经营数据与智能工具的工作台”。文字应从用户能完成的任务出发，不堆叠 LangGraph、RAG、MCP 等实现名词。

### 登录页

- 品牌：`知枢 Nexus`
- 主标题：`把企业问题交给知枢`
- 定位句：`连接企业知识、经营数据与智能工具的工作台`
- 说明：`知枢 Nexus 会根据问题自动选择合适的知识、数据和工具，并保留可核验的依据与执行过程。`
- 能力标签：`自然语言对话`、`知识检索`、`经营分析`、`受控工具调用`
- 主操作：`进入知枢工作台`

登录表单继续清楚展示演示身份、密码和权限差异。品牌文案不能挤占认证说明，也不能暗示公开演示具备正式多租户能力。

### 工作台

- 侧栏品牌：`知枢 Nexus`
- 侧栏副标题：`企业智能工作台`
- 空会话主标题：`今天要处理什么企业问题？`
- 空会话说明：`可以直接提问，也可以让知枢查知识、看数据或调用受控工具。`
- 助手消息名称：`知枢 AI`
- 加载状态：`正在连接知枢服务`
- 重要结论提示：`知枢生成的内容可能存在偏差，重要结论请核对引用、数据和执行记录。`

经营分析结果仍明确显示订单、商品、渠道、退款等具体业务范围。产品层使用“经营分析”，不把平台重新收窄成“零售分析工具”。

## 视觉标识

沿用现有明亮、精密、克制的企业工作台设计系统，不重新引入紫色品牌色、渐变背景、装饰光球或复杂插画。

- 主品牌色继续使用 `#0CA89B`，深色交互态使用 `#087F78`。
- 数据与链接继续使用 `#2563EB`，避免整个界面只有单一青绿色。
- 品牌字标使用“知枢”双字，不再使用单字“析”。
- 登录页和侧栏使用横向“知枢”字标；小尺寸助手头像使用上下两行“知/枢”，保证两个字在 28–32 px 区域内仍可识别。
- 助手头像必须提供 `aria-label="知枢 AI 助手"`；仅装饰性的重复字标对辅助技术隐藏。
- 不添加新的图标依赖。动作按钮继续使用项目现有 Lucide 图标，并保留可见焦点和无障碍名称。

品牌升级只调整字标、文案和必要间距，不重新改变用户已经认可的会话布局、固定输入框、移动端导航或结果展示结构。

## 前端状态与兼容迁移

localStorage 命名空间从 `retail-analytics:*` 迁移为 `zhishu-nexus:*`。首次加载时按以下顺序处理：

1. 优先读取新的 `zhishu-nexus:*` 键。
2. 新键不存在时读取对应旧键。
3. 将旧值写入新键并继续使用新命名空间。
4. 不主动删除旧键，保留一次回滚能力。

服务端会话才是跨设备会话的权威来源。本地命名空间迁移不能覆盖服务端较新的会话快照，也不能改变现有的删除同步和 5 秒轮询逻辑。

## 错误与回滚

- 如果 GitHub 仓库改名失败，本地目录不改名，保留原远程地址并报告失败原因。
- 如果本地目录改名失败，GitHub 新仓库仍可使用，但必须更新交接文档中的实际路径，不能声明不存在的本地路径。
- 如果部署检查失败，保留服务器旧目录并通过现有发布回滚机制恢复上一版本。
- localStorage 迁移发生解析错误时忽略损坏的旧值，不能阻塞登录或工作台加载；服务端会话仍可重新恢复数据。
