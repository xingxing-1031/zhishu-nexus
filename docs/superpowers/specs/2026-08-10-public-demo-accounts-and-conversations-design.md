# 公开演示账号与会话体验设计

日期：2026-08-10

状态：已确认，等待实现计划

## 目标

让面试官可以在公网完整体验“登录 -> 业务分析 -> 高风险审批 -> 结果与审计追溯”的真实工作流，同时保持公开演示数据隔离、权限边界清晰、交互状态可信。重点修复拒绝流程的错误成功状态、趋势图日期拥挤、低风险助手问答被拒绝、刷新丢失历史和单轮问答限制。

## 已确认范围

### 演示账号与权限

公开入口提供两个固定演示账号：

- 分析员：`analyst-demo` / `DemoAnalyst2026!`
- 管理员：`admin-demo` / `DemoAdmin2026!`

账号走真实后端登录和会话接口，不开放注册、改密或找回密码。两者只访问演示数据库。分析员可查询销售额、订单数、销量、退款金额、退款笔数和平均订单金额，但不能读取退款具体原因；管理员拥有分析员能力，并可查询敏感退款原因、处理审批和查看完整审批/审计记录。

公网页面明确说明这是固定演示身份与演示数据。前端不能自行提升角色，后端仍是权限、审批和审计的权威来源。

### 会话与上下文

浏览器本地按登录账号保存最近 8 个会话；每个会话最多保存最近 8 轮问答。用户可以新建、切换和删除会话，刷新页面后恢复。会话标题由首个问题生成短摘要。

默认每次提问独立执行。上一轮成功分析后，用户可显式选择“基于此结果继续”。继续请求只携带上一结果的结构化摘要（指标、维度、时间范围、筛选条件、结果字段和脱敏结论），不复用上一轮 SQL，也不绕过范围、权限、SQL 安全和业务一致性校验。

每个会话提供审计摘要：请求总数、成功/降级/拒绝数量、审批状态统计、平均耗时和最近活动时间。恢复历史时可查看该轮的结果、图表、表格和当前身份可见的审计依据。删除会话只删除浏览器历史，不删除服务端合规审计。

### 工作流状态

工作流由实际收到的事件驱动，不根据当前节点把前序节点批量标记为成功。状态语义如下：

- 绿色：已成功执行
- 蓝色：正在执行
- 灰色：未使用或未运行
- 黄色：等待审批
- 红色：拒绝或失败

拒绝时只标记实际到达的范围/权限/审批节点，后续节点均为灰色，并明确显示“未访问数据库”。助手答复和澄清请求只显示必要的识别/答复节点，分析节点灰色，不伪造七步分析。

### 助手答复与分析边界

确定性低风险问题（能力说明、当前上海时间、问候和确认）直接由助手答复，不调用数据库。缺少指标或时间范围的问题进入澄清。零售经营指标仍进入完整分析链路；越过支持指标、角色权限或只读安全边界的请求明确拒绝。

### 数据和图表

当前演示数据（130 条订单、16 个商品、4 个渠道、30 条退款、73 天覆盖）足够展示趋势、排名、渠道差异、商品表现和审批场景，不额外扩充。

公开查询返回上限保持 20 条。输入控件直接限制 `1-20` 并说明公开演示限制，避免浏览器原生校验弹窗。趋势图保留所有数据点，横轴使用短日期格式并按点数自动抽样标签；悬停显示完整日期、数值和单位。

## 数据流与未来扩展

当前浏览器本地记录使用 `user_id + conversation_id + message_id` 作为逻辑键，服务端请求继续使用后端生成的请求编号和审计记录。未来接入正式账号后，可将同一逻辑模型迁移到服务端会话表，以真实 `user_id` 隔离跨设备历史；前端会话操作接口保持不变，仅替换存储层。

服务端不把浏览器删除视为删除合规审计。公开环境不展示模型内部思考，仅展示节点状态、SQL 指纹、审批结果和可见依据。

## 错误处理

- 登录失败显示稳定的中文提示，不泄露账号是否存在以外的内部细节。
- 流式请求异常保留已收到的状态，失败节点标红，未执行节点灰色。
- 空结果显示查询成功但无匹配数据，不伪造趋势或结论。
- 追问无法从上一摘要确定口径时先澄清，不猜测时间范围、指标或维度。

## 验收与测试

覆盖以下行为：

1. 两个账号登录、退出及角色差异。
2. 分析员敏感字段拦截，管理员审批通过/拒绝，以及拒绝后数据库未执行。
3. 助手能力说明、上海时间和澄清请求不触发分析节点。
4. 工作流绿色/蓝色/灰色/黄色/红色状态与实际事件一致。
5. 趋势图日期标签不重叠且悬停保留完整日期。
6. 行数输入限制为 1-20。
7. 会话新建、切换、删除、刷新恢复和按账号隔离。
8. 显式上下文追问只使用结构化摘要并继续经过安全校验。
9. 会话审计摘要统计准确，移动端无横向溢出。

验证命令包括完整 `pytest`、前端 TypeScript 检查、Vite 构建，以及改动文件相关的静态检查和公网关键路径验收。
