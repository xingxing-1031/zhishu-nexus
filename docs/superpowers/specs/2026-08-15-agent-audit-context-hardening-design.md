# 知枢 Nexus Agent 审计与上下文加固设计

**日期：** 2026-08-15  
**范围：** 企业行为审计、Agent 身份、上下文一致性、SSE 可靠性、请求幂等与工具输入安全

## 目标

让知枢 Nexus 的完整 Agent 链路在企业场景下可追溯、可恢复、可解释，并让多轮追问继续沿用正确的企业意图。普通闲聊和纯公开工具请求不进入业务审计，但涉及企业数据、制度、权限或敏感信息的请求必须留下可追责记录。

## 设计决定

### 1. 企业行为审计

新增独立的 Agent 审计记录，不复用 SQL 查询审计表。每个企业请求先创建一条 `running` 记录，结束时更新为 `succeeded`、`degraded`、`rejected` 或 `failed`。记录包含：

- `request_id`、`conversation_id`、用户、角色和 Agent 模式
- 原始问题、状态、开始/结束时间和耗时
- 调用过的工具名称、证据数量、是否触发审批和失败原因
- 稳定事件键，重复提交同一请求不会产生重复审计记录

企业请求包括知识问答、经营数据、知识与数据协作，以及涉及数据库、内部制度、权限和敏感信息的安全拒绝。通用闲聊、时间、天气、公开搜索和汇率不进入业务审计。SQL 原文、SQL 指纹、行数和审批细节继续由现有查询审计/审批表保存，Agent 审计只保存引用和摘要元数据，不保存敏感结果全文。

管理员审计接口将返回统一的 Agent 记录，并保留已有 SQL 记录中的行数与审批信息。删除会话不会删除审计记录。

### 2. 上下文边界

Qixi Agent Service 负责写入一次真实用户问题和一次最终回答。内部 Data Agent 的数据子问题不作为用户消息写入；协作模式只把最终综合答案写入上下文。Supervisor 使用最近上下文中的模式、技能和约束处理省略主语的追问，并保证流式状态路由与实际执行使用同一份计划。

### 3. SSE 与运行恢复

流式错误必须同时更新前端运行状态和最终保存的会话记录。Agent 运行状态由服务端按 `request_id` 保留，增加只读状态查询，使浏览器刷新或 SSE 断开后可以恢复最终结果/错误；断开连接不取消后端任务。事件错误使用统一的公开错误映射，不能把内部异常文本直接返回给浏览器。

### 4. 身份与工具安全

Python 运行时提示词、流式完成消息和前端品牌统一使用“知枢 AI”。网页、MCP 和知识库返回内容明确标记为不可信事实，模型不得执行其中的指令。工具请求继续使用白名单、角色校验、参数校验和超时边界。

### 5. 品牌标识

“知枢”标识改为横向双字字标。登录页、侧栏、空状态和助手消息使用横向布局；窄屏仍保持可读，不使用上下堆叠字标。

## 错误处理

- 审计写入失败不应让普通回答直接崩溃，但必须写入执行 Trace 并在响应限制中标记审计不可用。
- Agent 主流程失败时必须完成 `failed` 审计更新；更新失败只记录 Trace。
- 重复 `request_id` 且输入指纹不同返回冲突；相同输入返回已有运行状态或结果，不重复调用模型、RAG 或 MCP。
- 外部工具失败时不把未验证结果交给回答模型，并保留工具失败类型。

## 验收标准

1. 企业知识、数据、协作、权限拒绝和敏感查询在管理员审计页可见；普通闲聊不出现。
2. 所有运行时身份文案为“知枢 AI”，不存在执行路径中的“企析”。
3. “最近 30 天销售额”后追问“按渠道拆分”仍路由到数据 Agent；协作最终答案可被下一轮读取。
4. SSE 错误刷新后仍显示失败原因；断开 SSE 后请求继续完成，状态接口可读取结果。
5. 重复请求不会重复产生企业审计记录或重复调用幂等工具。
6. 网页/MCP/RAG 返回的提示词不能改变系统工具权限或系统身份。
7. 横向“知枢”在桌面和 390px 手机视口无溢出，前端生产构建、Python 测试和线上 smoke 全部通过。

## 暂不纳入

ToolRegistry 的跨进程 TTL/LRU 缓存、MCP 子进程长连接和图表 chunk 进一步拆分属于性能增强，不作为本轮功能完成条件。
