# W4-3 手机学习卡：向量检索、混合召回与重排

## 1. 本阶段解决什么问题

W4-2 能根据已经结构化的 `AnalysisPlan` 确定性选择指标、表和 JOIN，但用户最初输入的是自然语言。W4-3 要验证不同自然语言检索方法能否找到正确指标，并建立可重复的评测证据。

```text
用户问题
→ 域判断
→ 关键词召回 + 向量召回
→ RRF 融合
→ Reranker 选择最小充分指标
→ 确定性目录补全公式、表和 JOIN
```

语义模型只负责寻找指标候选，不能自己猜测表和 JOIN。候选指标确定后，仍由 `CatalogRetrievalTool` 根据批准目录补全完整业务证据。

## 2. 为什么需要 Gold Set

Gold Set 是人工独立标注的标准答案集合。每条案例包含用户问题和预期指标，不能让被测检索器生成自己的答案，否则实现错误会同时污染标准答案，形成循环自证。

本阶段评估：

```text
Precision@K：返回的候选中有多少是正确的
Recall@K：标准答案中有多少被成功找回
Exact Match：返回集合是否与标准答案完全一致
Empty Accuracy：不支持问题是否正确返回空结果
```

## 3. 为什么按完整语义单元分块

一个指标块必须同时保存：

```text
指标名称和别名
业务定义和公式
固定筛选规则
来源表和字段
支持维度
版本和 source_id
```

若只召回销售额公式，却漏掉 `orders.status = 'paid'`，SQL 可能统计所有订单状态。分块边界应服从业务语义，不能只按固定字符数机械切分。

当前知识库有 13 块：6 个指标、4 张表和 3 条 JOIN。

## 4. Embedding 和 pgvector 做什么

`bge-m3` 把知识文本和用户问题转换为 1024 维向量。PostgreSQL 的 pgvector 保存知识向量，并使用余弦距离查找语义上相近的内容。

```text
知识文本 → bge-m3 → 1024 维向量 → knowledge_chunks
用户问题 → bge-m3 → 1024 维向量 → 余弦距离排序
```

知识向量和查询向量必须使用相同模型、版本、维度和预处理方式。不同模型生成的向量属于不同语义坐标系，不能可靠比较。

`content_sha256` 用于发现知识内容已经变化、旧向量需要重新生成。当前只有 13 块知识，使用精确搜索即可，不需要提前增加 HNSW 或 IVFFlat 近似索引。

## 5. 关键词检索的优缺点

关键词检索按“销售额、订单量、客单价”等明确别名匹配。

优点：

```text
速度快
结果稳定
容易解释
明确术语的精确率高
```

缺点是无法穷举所有表达。例如“最近卖了多少钱”和“每张单子平均花了多少钱”没有直接出现标准别名时可能召回失败。

初始关键词基线在 10 条支持问题上的平均精确率和召回率均为 60%。不能为了让测试达到 100%，把失败问题逐条加入别名；那只是对测试集背答案。

## 6. 向量检索的优缺点

向量检索根据语义相似度召回，因此能处理没有出现标准关键词的同义表达。

未加阈值的真实 `bge-m3` Top-5 检索得到：

```text
Recall@5 = 100%
Precision@5 = 22%
域外准确率 = 0%
```

这表示正确指标全部进入了候选，但同时混入许多无关指标。向量 Top-K 总会返回相对最近的内容；即使问题是天气，也会从零售指标中找出几个“最不远”的候选。

因此向量召回的结果是候选集合，不是最终业务答案。

## 7. RRF 为什么不直接相加分数

关键词分数和向量距离的量纲、范围及分布不同，直接相加会让数值较大的一路长期支配结果。

RRF 只使用各路排名：

```text
RRF 分数 = Σ 1 / (常数 + 当前排名)
```

某个指标在关键词和向量两路都靠前，会获得两次排名积分；只在一路靠前的指标积分通常较低。

真实混合召回未使用严格阈值时，Top-1 精确率达到 100%，召回率为 95%。95% 而不是 100%，是因为一个双指标问题需要两个答案，而 Top-1 最多只能返回一个。

## 8. 为什么严格距离阈值失败

验证集选择出的距离阈值约为 `0.475`，在验证集上的平衡准确率为 91.7%。它能拒绝天气问题，但放到独立测试集后，也错误过滤了：

```text
最近卖了多少钱
总共卖出去多少件
```

混合 Top-1 召回率因此从 95% 降到 75%。

阈值严格时噪声减少，但正确同义表达也可能被拒绝；阈值宽松时召回提高，但域外问题会进入候选。距离阈值可以作为风险信号，不能单独承担候选召回、业务能力判断和最终选择三项职责。

## 9. Reranker 做什么

Reranker 接收粗召回后的完整候选，重新比较用户问题与每个指标的关系，选择最小充分指标集合。

它可以：

```text
单选：卖了多少钱 → sales_amount
多选：退款金额和退款笔数 → 两个指标
拒绝：问题不属于候选能力 → 空集合
```

Reranker 必须看到阈值过滤前的高召回候选。如果正确指标已被前一层删除，Reranker 无法凭空恢复。

本项目当前使用的是 `qwen3:4b` 列表式 LLM Reranker，不是专用 Cross-Encoder，报告必须如实标明模型类型。

## 10. 为什么还需要域判断门

Reranker 的职责是从已有候选中选择指标，不等于判断整个问题是否属于系统能力范围。真实实验中，Reranker 能准确选择支持问题的指标，却仍可能把天气问题映射到零售候选。

域判断门先判断问题是否属于当前六类已批准指标：

```text
sales_amount
order_count
units_sold
refund_amount
refund_count
average_order_value
```

“与零售相关”不等于“当前系统支持”。库存、发货、商品当前价格、客户隐私和毛利润都属于零售话题，但缺少已批准指标定义或必要数据时必须拒绝。

## 11. 模型大小与真实对照

同一候选集上：

```text
qwen3:0.6b：召回率 100%，精确率 42.5%，经常多选无关指标
qwen3:4b：支持问题的精确率和召回率均为 100%
```

这只证明 4B 模型在当前小型评测和提示下表现更好，不证明参数越大永远越好，也不证明上线数据一定保持相同结果。模型选择必须同时比较准确率、延迟、资源占用和稳定性。

## 12. 为什么要区分开发集和留出集

如果看到测试失败后修改提示词，再在同一批题上测试，测试题已经参与开发，这叫测试集泄漏。提高后的分数只能说明系统记住了这批表达，不能证明泛化能力。

本阶段发现提示示例与原 Gold Set 过近后，将原集合降级为开发集，并新建 20 条未参与调参的最终留出集，只运行一次：

```text
12 条支持问题：Precision = 100%，Recall = 100%
8 条不支持问题：正确拒绝 5 条，Empty Accuracy = 62.5%
总体 Exact Match = 85%
```

失败问题是未发货订单数、商品当前价格和毛利润。该 85% 是当前可信结果，不能根据这三题立即修改提示后继续称为最终留出成绩。

## 13. 当前能力边界

本阶段已证明：

```text
bge-m3 能生成真实 1024 维向量
13 个知识块已写入真实 PostgreSQL/pgvector
关键词、向量、RRF、LLM Reranker 和域判断可以串联运行
180 项 Python 测试通过
```

本阶段没有证明：

```text
所有自然语言都能被正确理解
所有零售问题都属于当前六个指标
真实模型已接入完整 LangGraph SQL 生成和回答链路
85% 可以直接当成生产准确率或简历中的最终指标
```

W4-4 才会继续打通自然语言计划、业务证据、安全 SQL、查询结果和最终回答。

## 15. 自测题标准答案

### 1. W4-2 与 W4-3 分别解决什么问题？

W4-2 根据结构化分析计划确定性补全指标、表和 JOIN 证据；W4-3 比较自然语言的关键词、向量、混合召回和重排效果，并建立真实评测证据。

### 2. 为什么 Gold Set 必须由人工独立标注？

若让被测检索器生成标准答案，实现错误会同时污染预期结果，形成循环自证。人工依据业务定义独立标注，才能客观比较实际输出。

### 3. Precision@K 和 Recall@K 分别表示什么？

Precision@K 表示返回候选中正确项的比例；Recall@K 表示标准答案中被成功找回的比例。粗召回通常优先保证召回率，后续重排再提高精确率。

### 4. 为什么指标公式和固定筛选必须放在同一个语义块？

两者共同定义完整业务口径。拆开后可能只召回公式却漏掉已支付等固定规则，使 SQL 语法正确但业务计算错误。

### 5. 为什么知识向量和查询向量必须使用同一 Embedding 模型？

不同模型的向量属于不同语义坐标系，即使维度相同也不能可靠计算距离；模型、版本、维度和预处理必须保持一致。

### 6. 关键词检索和向量检索各自的优势是什么？

关键词检索对明确术语快速、稳定、精确且可解释；向量检索能处理同义表达和字面不同但含义相近的问题，减少正确候选遗漏。

### 7. 为什么天气问题也会被向量 Top-K 返回候选？

Top-K 要求返回距离最近的若干项，即使所有知识都不相关，也会选出相对最近的内容。最近不等于足够相关，因此还需要能力边界和后续判断。

### 8. RRF 为什么不直接相加关键词分数与向量距离？

两种原始分数的量纲、范围和分布不同，直接相加没有稳定含义。RRF 使用各路排名计算积分，不要求原始分数处于同一尺度。

### 9. 为什么混合 Top-1 全部选对时，召回率仍可能是 95%？

一个双指标问题需要两个正确结果，但 Top-1 最多返回一个，该案例只能召回一半；对 9 个单指标满召回和 1 个双指标半召回取平均得到 95%。

### 10. 严格距离阈值为什么可能降低召回率？

自然语言同义表达的向量距离可能不够近。阈值过严会把合法但表达不同的问题连同噪声一起过滤，产生假阴性。

### 11. 为什么 Reranker 必须看到完整候选？

Reranker只能在收到的候选中比较和选择。如果正确指标在粗召回或阈值阶段已经被删除，后续模型无法凭空恢复。

### 12. Reranker 和域判断门的职责有什么区别？

Reranker 在候选中选择用户明确需要的最小充分指标集合；域判断门判断整个问题是否属于当前已批准的指标能力范围，并在不支持时阻止后续处理。

### 13. 为什么“毛利润”属于零售问题却仍应被当前系统拒绝？

当前没有成本字段和经过批准的毛利润公式。零售相关性不能代替数据与业务口径，强行映射到销售额会返回错误业务答案。

### 14. 为什么不能根据最终留出集失败案例立即改提示并重新宣称最终准确率？

一旦根据失败案例调整系统，留出集就参与了开发并发生测试泄漏。再次评估需要新的、从未参与修改的独立留出集。

### 15. 当前 85% 留出结果能证明什么，不能证明什么？

它证明当前版本在这 20 条未参与调参的样本上完全匹配 85%，且支持问题识别较好、细粒度能力边界仍有缺陷；它不能证明生产准确率、所有自然语言泛化能力或完整 Agent 已经完成。
