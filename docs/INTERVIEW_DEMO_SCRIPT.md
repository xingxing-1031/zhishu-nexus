# 3 分钟面试演示脚本

公网地址：`http://106.52.176.63/`

## 演示前准备

- 打开公网地址，确认登录页同时列出分析员和管理员演示账号及各自权限。
- 先使用 `analyst-demo / DemoAnalyst2026!` 登录；管理员阶段使用 `admin-demo / DemoAdmin2026!`。
- 展示时优先使用桌面浏览器；手机端用于补充说明响应式布局。

## 0:00 - 0:25 项目问题与边界

“这是一个面向零售运营人员的可审计数据分析 Agent。运营同学可以用自然语言查询订单、商品、渠道和退款数据，但系统不会让前端直接访问数据库，也不会把模型生成的内容直接当成 SQL 执行。”

指向页面顶部数据概况和“可信说明”：当前公开演示有 130 条订单、16 个商品、4 个渠道、30 条退款、73 天数据覆盖。说明这些是可复现演示数据，不是伪造的前端卡片。

## 0:25 - 1:10 真实经营分析

在“业务问题”中输入或选择“渠道经营”示例：

```text
统计最近30天各销售渠道的销售额，按销售额从高到低排序，返回10条。
```

点击“运行分析”。等待过程中讲解“分析工作流”会经过计划、证据检索、查询生成、安全校验、业务校验、数据执行和结论生成。

完成后依次指出：

- 结论卡：中文经营结论和查询状态。
- 数据图表与结果表格：真实结构化结果，不是模型编造的段落。
- 审计依据：分析计划、指标/表关联证据、以及销售额的业务口径约束。

可以补充一句：“销售额固定统计已支付订单，并基于订单明细成交价快照计算，所以后续商品改价不会改写历史分析。”

## 1:10 - 1:40 分析员安全边界

输入：

```text
查询最近30天的退款原因，并按原因统计金额。
```

点击“运行分析”。页面应显示“本次请求在数据库执行前被拒绝”，原因是公开身份为分析员，无权读取退款原因这一敏感字段。

说明：“这里的重点不是让模型回答拒绝理由，而是请求在访问数据库之前被服务端权限和 SQL 安全边界拦截，因此不会返回敏感数据。”

## 1:40 - 2:25 管理员审批与审计

退出分析员账号，使用公开管理员演示账号登录。输入：

```text
查看最近 10 条退款记录的退款原因。
```

管理员发起高风险敏感字段查询后，页面展示只读 SQL 预览、SQL 指纹、敏感字段和预计行数；批准后执行的 SQL 与预览保持一致，拒绝则在执行前结束。批准/拒绝和结果会写入审计记录。强调两个账号只操作演示数据库，角色仍由服务端会话决定，前端不能自行切换。

## 2:25 - 3:00 会话、上下文与项目边界

指出左侧可以新建、切换和删除本浏览器会话；刷新后仍保留最近 8 个会话、每会话最近 8 轮。点击“基于此结果继续”只传递上一轮的结构化指标摘要，新的追问仍经过完整权限和 SQL 校验。会话审计摘要显示完成、拒绝、失败、审批等待和平均耗时。

收尾：

“这个项目的重点不是堆功能，而是把自然语言分析、业务口径、安全校验、审批和审计串成一条可解释链路。它是单 VPS 的受限演示，不把共享公开身份包装成正式多租户生产系统。”

## 不应做出的表述

- 不说“公开账号等同于正式生产账号体系”或“浏览器历史已经跨设备同步”。
- 不说“已经完成用户注册、多租户服务端历史、HTTPS、分布式限流或高可用生产部署”。
- 不把开发集或已经消费的 frozen holdout 成绩表述为泛化准确率。
- 不把 130 条演示订单说成真实企业规模数据。
