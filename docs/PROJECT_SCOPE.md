# 项目范围

## 业务问题

让不懂 SQL 的零售运营人员能够安全、可追溯地分析订单、商品、渠道和退款数据。

## 核心工作流

```text
自然语言问题
-> 检索指标口径和 Schema
-> 生成结构化分析计划
-> 生成并校验只读 SQL
-> 执行查询
-> 生成图表规格
-> 输出结论、SQL、指标口径和数据来源
```

## 暑假必须完成

- PostgreSQL 业务数据与指标字典
- SQLGlot AST 安全校验
- LangGraph 状态工作流与 Checkpointer
- 指标和 Schema 检索
- 图表规格与 SSE 状态输出
- 权限、人工确认、超时、重试和审计
- 至少 100 条独立评测数据
- Docker Compose、pytest 和 GitHub Actions

## 暑假明确不做

- 泛化到任意行业和任意数据库
- PDF/OCR 全格式解析
- 为了数量拆分多个 Sub-agent
- K8s 生产部署
- 复杂微服务拆分
- 没有评测依据的简历指标

## 当前边界和非目标（可迁移销售数据）

- **可迁移不等于任意零配置接入**：只支持符合接入契约的销售 CSV/Parquet；字段画像给候选角色，业务口径必须管理员确认，模型建议不能直接生效。
- **单数据集范围**：Agent 每次分析只能访问当前选中的就绪数据集及其 staging schema，不允许跨数据集 JOIN；`failed`/`archived`/未确认映射的数据集不能被分析员使用。
- **指标范围**：首期只支持能明确验证的聚合（销售额、订单数、销量、平均订单金额及渠道/区域/品类维度）；退款率、复购率等需要额外状态或客户口径的指标，字段不足时不自动发布。
- **不承诺生产级能力**：单文件导入、单进程限流、演示级身份与角色、无租户级隔离；不是注册系统、分布式限流、高并发或正式多租户产品。
- **未运行不编造**：跨数据集真实链路评分需要模型与数据库，未运行前不写通过率或提升幅度；README 只引用已保存原始记录的指标。
